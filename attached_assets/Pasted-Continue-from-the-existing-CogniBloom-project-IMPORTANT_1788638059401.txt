==================================================
PRODUCT CONCEPT
==================================================

CogniBloom is an Active Learning Tutor.

The problem is:

Student asks AI a question
→ AI gives technically correct explanation
→ student reads it
→ student leaves

Our product changes this to:

Student asks question
↓
AI explanation
↓
"Let's check your understanding"
↓
Student explains the concept in their own words
↓
System evaluates response
↓
Targeted feedback
↓
Retry OR continue
↓
Learning session completion

The concept-check interaction is the CORE product feature.

==================================================
SCREEN 1 — START LEARNING
==================================================

Create a clean starting screen.

The student should enter:

Topic
Question

Example:

Topic:
Photosynthesis

Question:
What is photosynthesis?

Primary button:

"Start Learning"

Validation:
- topic cannot be empty
- question cannot be empty
- show clear inline validation

When submitted:

1. Call POST /api/sessions
2. Store the returned session ID
3. Call POST /api/questions
4. Move to the explanation stage

Show a loading state while the API calls are running.

Prevent duplicate submissions.

==================================================
SCREEN 2 — AI EXPLANATION
==================================================

Display:

- topic
- student's question
- AI explanation

Use the explanation returned by the backend.

IMPORTANT:

Do NOT show a final "Done" button immediately after the explanation.

Instead create a clear transition:

"Now let's check your understanding."

Then show the concept-check interaction.

==================================================
SCREEN 3 — CONCEPT CHECK
==================================================

Display one short-answer learning challenge.

Example:

"Explain in your own words what photosynthesis is and what plants need for it."

Provide:

- textarea
- Submit Answer button
- Skip button

The UI should make it obvious that the student is expected to THINK and respond, not simply read.

Do not add multiple quizzes or multiple learning activities.

Keep ONE strong interaction.

==================================================
SCREEN 4 — FEEDBACK
==================================================

After submitting:

Call:

POST /api/interactions

using the existing API contract.

Display the returned:

- evaluation
- feedback
- nextAction

Possible evaluation:

correct
partially_correct
incorrect

Possible nextAction:

COMPLETE
RETRY
SIMPLIFY

For a correct response:

Show a positive but restrained success state.

Provide:

"Continue Learning"
"Finish Session"

For an incorrect or partially correct response:

Show constructive feedback.

Allow another attempt.

If the backend returns SIMPLIFY:

Clearly communicate that the explanation is being simplified / that the student can try again with additional guidance.

IMPORTANT:
Do not invent a different evaluation system in the frontend.

Use the backend's response.

==================================================

The backend already supports:

Use this to restore a session if the page is refreshed.

Store the session ID in an appropriate way such as URL state or localStorage.

On page load:

- return the user to the start screen
